Three things on the pages themselves work against them. Every one of the nine carries the same generated meta description, “Get exceptional tummy tuck miami results with Miami's top surgeons…”, with the procedure name dropped in lowercase. The site tells two different price stories: the tummy tuck page says from $3,500 and the mommy makeover page $7,000–$20,000, while the blog post that outranks both says $8,000–$12,000 and $15,000–$25,000. And the largest commercial query on the site, “tummy tuck cost miami” with 3,322 impressions in 28 days, is answered by a blog post about combining a tummy tuck with a mommy makeover, at position 8, with one click.

Technical findings

  • fix firstcodeThe blog sitemap's modified dates are driven by the page-view counter.

    blog_post.updated_at is set on every row update, the views endpoint increments views on the same row, and sitemap/blog.xml uses updatedAt as lastmod. Result: the most-read posts report a fresh modification every day (25 posts “modified” in the last 7 days, 115 in the second half of August, zero content revisions in the database). Google learns to ignore a lastmod that lies, which removes the one signal that would get a genuinely refreshed post recrawled. Move view counts off the post row or preserve updatedAt in that write, and derive lastmod from content changes.

  • fix firstcode/bbl-miami duplicates the BBL procedure page.

    A lead-gen landing page, indexed, with the same declared targets (“bbl miami”, “brazilian butt lift miami”, “best bbl surgeon miami”). Redirect it to /procedures/brazilian-butt-lift-bbl-miami, or noindex it if a paid campaign still lands there.

  • quickcodeFour URLs that still earn impressions return 404.

    Two legacy slugs, /blog/breast-implants-drop-fluff-timeline-what-to-expect-month-by-month-after-breast-augmentation and /blog/breast-implants-drop-implant-timeline-tips, and two near-miss slugs, /blog/swelling-and-asymmetry-after-augmentation-faq and /blog/when-can-you-workout-after-breast-augmentation. Each has a live twin; add permanent redirects.

  • quickcodeProcedure meta descriptions are one template.

    Write nine descriptions that say what the page says: the starting price, the technique, the surgeon, the free consultation.

  • quickcodeTwo specials pages, two reviews targets.

    /promotions and /miami-plastic-surgery-specials split “specials” queries; the homepage and /about outrank /reviews for “alluring plastic surgery reviews”, and /reviews lost five positions in the two weeks after it was paginated. One canonical URL per intent, titled for it, linked with that anchor.

  • housekeepingInstagram sitemap shows an error in Search Console.

    Intentional: the route returns an empty list because the 800 Instagram pages were noindexed. Remove the submission in Search Console, then delete the route as its own comment suggests.

  • housekeepingThe Google Business Profile link shows up as a separate page.

    /?utm_source=google…gbp-listing is credited with 125 clicks. The canonical is clean, so nothing to fix; just read it as the homepage when comparing pages.

Why it keeps happening

Of the four posts the pipeline published in the last 45 days, two landed on questions the site already ranked for: the work-out-after-augmentation post beside the push-ups post, and the swelling FAQ beside an existing asymmetry page (that one, at least, is winning). The review board does include a cannibalization checker, but it compares a draft against a static keyword-ownership registry, not against the live list of published posts and what Search Console says already ranks. Feed it both: the published slugs, titles and primary keywords, plus the pages-for-query lookup for the draft's head terms, and block a draft outright when an existing page is already in the top 20. The same lookup belongs in the ideation gate, so the topic is rejected before a draft costs anything.

Plan

    This week · code only · no content decisions needed
    • Fix sitemap lastmod (view counter off the post row; lastmod from content changes).
    • Permanent redirects for the four 404 URLs; redirect or noindex /bbl-miami; pick one specials URL and redirect the other.
    • Nine hand-written procedure meta descriptions; titles that name the head term first (“Tummy Tuck in Miami”, not “Tummy Tuck Miami 2026”).
    • One price table per procedure, sourced from the procedure data, reused by every blog post that quotes a price.
    • Remove the Instagram sitemap submission in Search Console.

  2. Give the money pages their queries back

    Weeks 2–3 · content + internal links
    • Each procedure page gets a “Cost in Miami” section that answers the query in its first sentence, an FAQ item for it, and the head-term anchor in the first screen of every related blog post.
    • The cost-intent blog posts (tummy-tuck-mommy-makeover-miami, affordable-plastic-surgery-miami) are retitled to the decision they actually help with and link up, not sideways.
    • Consolidate the informational clusters: BBL recovery 7→3, tummy tuck recovery 5→2, mommy makeover recovery 3→2, breast augmentation exercise 3→1, liposuction recovery 3→2, board-certified 3→1. Each merge keeps the strongest URL, folds the others' unique content in, and redirects.
    • Rewrite the top five decaying question posts (BBL smell, pubic swelling, BBL vs tummy tuck pain, sleeping after reduction, stitches) answer-first, so the AI Overview quotes them instead of replacing them.

  3. Make it stay fixed

    Week 4 onward · pipeline + measurement
    • Cannibalization checker and ideation gate read the live corpus and Search Console before a topic is approved.
    • Re-run the query-by-page sweep monthly (the script exists; it belongs in the Search Console MCP server as a cannibalization tool next to pages_for_query).
    • Four weeks after phase 2, if a procedure page still trails its own blog post for the cost query, redirect the post into the page.
    • Track one number per procedure: clicks on the procedure page for its head term and cost term. Today that number is zero for six of nine.
